# 세탁실 대기 시스템 제안

대기 순서대로 먼저 비는 기기를 배정하는 방식을 제안한다. 이 문서는 검토안이며, 대기 기능이 구현됐거나 운영 규칙이 확정됐다는 뜻은 아니다.

## 확인된 조건

- 2생활관 여자와 남자 구역은 각각 1층에 세탁기 12대와 건조기 6대가 있다.
- 기본 사용 시간은 세탁 36분, 건조 45분이다.
- 3생활관 여자와 남자 구역은 각각 2층부터 5층까지 각 층에 세탁기 2대와 건조기 1대가 있다.
- 다른 층을 이용할 수 있다. 같은 생활관의 남녀 구역은 시설 구성이 같지만 별도 기기와 대기열로 관리한다.
- 현재는 센서 없이 이용자가 QR로 시작과 남은 시간을 등록한다.

위 시설 정보는 2026년 11월 4일까지 이 프로젝트 대화에서 사용자가 확인한 내용이다. 실제 대기 운영에 참여하기로 확인된 기기만 배정 대상에 넣는다.

## 제안하는 기본 규칙

1. 생활관, 남녀 구역, 기기 종류별로 선착순 대기열을 만든다. 같은 대기열 안에서는 층보다 빈 기기를 우선한다.
2. 순서는 이용자 기기의 시계가 아니라 서버가 접수한 순번으로 결정한다.
3. 한 사람은 같은 종류에서 종료되지 않은 대기와 배정 기록을 합쳐 하나만 가질 수 있다. 알림 실패로 확인을 기다리는 기록도 포함한다.
4. 호출되면 바로 사용할 준비가 된 사람만 대기한다. 세탁 시작과 동시에 건조 대기를 자동 등록하지 않는다.
5. 여러 기기가 동시에 비면 앞선 사람부터 서로 다른 기기를 배정한다. 한 사람이나 한 기기에 배정이 중복되지 않도록 함께 확정한다.
6. 대기자가 있으면 새로 온 사람이 즉시 시작할 수 없다. 대기자가 없으면 같은 배정 절차를 통해 바로 사용한다.
7. 호출받은 이용자가 배정된 기기의 QR을 열어 시작을 확정한다. 기기와 이용자, 배정 기록이 모두 일치해야 한다.
8. 이용자는 자기 대기와 배정을 취소할 수 있다. 호출 기한이 지나면 배정을 해제하고 다음 사람에게 넘기며, 노쇼 후 재등록하면 맨 뒤에 선다.

## 기기와 대기 상태를 분리한다

| 대상 | 제안 상태 |
| --- | --- |
| 기기 | 미확인, 사용 중, 수거 대기, 사용 가능, 점검 필요 |
| 이용자 대기 | 대기 중, 호출됨, 확인 대기, 사용 시작, 취소됨, 호출 만료 |

예상 종료 시각이 지나도 기기를 사용 가능으로 바꾸지 않는다. 이전 이용자의 수거 완료 또는 현장 확인으로 비어 있음을 확인한 뒤 다음 사람을 호출한다. 미등록 기기도 빈 기기로 간주하지 않는다.

호출받고 갔는데 빨래가 남아 있으면 기기를 수거 대기로 되돌린다. 고장이면 점검 필요로 바꿔 배정 대상에서 제외한다. 두 경우 모두 이용자의 원래 순번을 보존하고 노쇼로 처리하지 않는다. 해결된 기기는 다시 확인한 뒤 배정 대상에 넣는다.

## 초기 시험값과 미확정 사항

- 호출부터 QR 시작까지 **5분**을 초기 시험값으로 제안한다. 층간 이동 시간과 기기가 비어 있는 시간을 측정해 조정한다.
- 호출 기한은 서버 시각으로 계산한다. 화면을 닫거나 휴대폰 시간을 바꿔도 연장되지 않는다.
- 탭을 닫아도 대기 기록은 유지한다. 다시 접속하면 서버의 현재 순번과 배정 상태를 보여준다.
- 알림 실패가 확인되면 배정을 해제하고, 이용자를 원래 순번을 가진 확인 대기 상태로 둔다. 재접속해 이용 준비를 확인하기 전에는 다시 호출하지 않아 같은 사람 때문에 기기가 계속 비지 않게 한다.
- 알림을 보냈다는 사실과 이용자가 확인했다는 사실을 구분한다. 알림 전달 상태를 알 수 없는 경우의 재알림과 호출 만료 규칙은 서비스 선택과 운영 시험으로 확정해야 한다.
- 초기에는 노쇼 누적 벌점이나 장기 이용 제한을 추가하지 않는다. 알림 실패를 이용자 잘못으로 단정하지 않는다.

## 필요한 데이터와 권한

- 이용자: 안정적인 식별자와 인증 정보. 브라우저 저장값만으로는 여러 기기의 동일인을 확실히 구분할 수 없다.
- 기기: 생활관, 구역, 층, 종류, 운영 참여 여부, 상태와 상태 버전.
- 사용 기록: 이용자, 기기, 사용 기록 ID, 시작 시각, 예상 종료 시각, 수거 확인 시각.
- 대기 기록: 이용자, 대기열, 서버 순번, 상태, 배정 기기, 배정 ID, 호출 시각과 만료 시각, 알림 상태.
- 변경 요청: 요청 ID와 대상 기록 ID, 예상 버전. 같은 요청이 재전송돼도 한 번만 반영한다.

조회와 수정 권한을 구분한다. 본인의 사용 시간과 대기만 수정하고, 다른 사람의 기록 정정과 고장 복구에는 별도 운영 권한을 둔다. 현장 확인은 다른 사람의 사용 시간을 임의 변경하는 기능과 구분한다.

오래된 화면에서 보낸 취소나 수거 완료가 새 이용자의 기록을 지우면 안 된다. 기기 번호뿐 아니라 현재 사용 또는 배정 ID와 버전을 비교한다. 만료 판정과 다음 사람 배정도 함께 처리해 만료 직후 늦게 도착한 이전 사용자의 시작 요청을 거절한다.

## 예상 대기와 처리량

대기 시간을 `앞사람 수 × 45분`으로 계산하지 않는다. 여러 건조기가 동시에 돌아가므로 각 기기의 예상 종료 시각과 배정 상태를 기준으로, 가장 먼저 비는 기기에 앞사람을 차례로 넣어 추정한다. 수거 지연과 노쇼 때문에 달라질 수 있는 예상값으로 표시한다.

2생활관 남자 1층에서 모든 기기가 같은 조건으로 계속 돌고 수거 시간이 0이라고 가정하면, 세탁은 `12 × 60 ÷ 36 = 시간당 20회`, 건조는 `6 × 60 ÷ 45 = 시간당 8회`다. 세탁 1회분마다 건조 1회가 필요하다는 추가 가정에서 건조기 병목 가능성을 보여주는 계산이다. 실제 이용률이나 처리량을 측정한 결과는 아니다.

## 구현 전 통과할 핵심 검증

- 같은 사람이 여러 번 눌러도 종류별 활성 대기와 배정이 하나만 생긴다.
- 여러 기기의 동시 수거 완료와 여러 이용자의 동시 시작에서도 이중 배정이 없다.
- 예상 종료만으로는 호출하지 않고, 수거 완료 또는 현장 확인 뒤에만 호출한다.
- 호출 기한 전후의 시작, 취소, 재시도에서 순번과 기기 상태가 일관된다.
- 이전 사용 기록의 늦은 요청이 새 사용 기록에 영향을 주지 않는다.
- 빨래 미수거와 고장 신고 때 순번을 보존하고 해당 기기는 배정에서 제외한다.
- 화면 닫기, 재접속, 알림 실패와 늦은 알림을 실제 휴대폰에서 시험한다.
- 다른 사람의 대기 취소와 시간 수정 요청은 거절한다.

## 구현 범위와 다음 결정

기존 TypeScript, Cloudflare Workers, D1을 유지하는 방향으로 설계할 수 있다. 먼저 한 세탁실에서 순번과 배정 일관성을 검증한다. 이용자 인증, 운영자 권한, 알림 방식과 비용은 후속 결정이며 새 서비스 도입을 전제로 하지 않는다.

이 시스템은 웹에서의 순서를 관리한다. 센서나 기기 제어가 없으므로 실제 기기를 먼저 작동시키는 행동을 물리적으로 막을 수 없다. QR은 위치를 가리키는 표식이며, 사진이나 링크를 공유할 수 있어 현장 도착의 증명도 아니다. 현장 안내와 이용자 준수를 포함해 시험해야 한다.
