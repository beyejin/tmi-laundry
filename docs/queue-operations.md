# 대기제 구현과 시범 운영

학교 계정의 사용 기록을 기준으로 수거할 사람과 다음 이용자에게 각각 Web Push를 보냅니다. 3생활관 여자 2층부터 5층의 세탁기 8대와 건조기 4대를 종류별 공용 대기줄로 관리합니다.

현재 코드의 기본 설정은 `QUEUE_ENABLED=false`입니다. 기존 현황판을 유지하며 로그인, 운영자, 알림 설정과 현장 확인이 끝난 뒤 대기제를 활성화합니다. 구현 완료와 실제 휴대폰 알림 검증은 구분합니다.

## 이용 규칙

1. 학교 Google 조직 도메인 `gachon.ac.kr`, `gc.gachon.ac.kr`을 서버에서 검증합니다. Google 고유 식별자 `sub`가 계정 ID이며 거주 여부를 따로 인증하지 않습니다.
2. 종류별로 준비 전, 대기, 호출, 알림 실패 보류, 사용, 수거 대기를 합쳐 2장까지 등록합니다. 대기표 한 장은 한 대에 배정합니다.
3. 세탁은 바로 준비 완료로 등록합니다. 건조는 대기표마다 준비 완료를 눌러야 배정합니다.
4. 준비된 대기표 중 접수 순번이 앞선 순서로 배정합니다. 준비 전 대기표는 원래 순번을 유지합니다.
5. 예상 종료에 현재 이용자의 수거 알림과 다음 이용자의 현장 확인 알림을 따로 예약합니다. 대기자가 없어도 수거 알림은 예약합니다.
6. 다음 이용자는 호출 후 5분 안에 해당 기기 QR에서 빈 상태와 실제 시작을 확인합니다. 알림 링크와 현황판 선택은 QR 확인을 대신하지 않습니다.
7. 알림 전송 접수 후 미응답으로 호출이 만료되면 벌점 없이 종료합니다. 다시 등록하면 새로운 순번을 받습니다. 알림이 3회 모두 실패하거나 호출 기한 안에 전송 접수를 확인하지 못하면 호출을 해제하고 원래 순번으로 보류합니다.
8. 본인만 시간을 수정합니다. 이미 호출된 사람이 있으면 호출을 해제하고 그 사람의 순번을 복원합니다.

시간은 센서 측정값이 아닌 예상값입니다. 정적 QR 주소는 재사용할 수 있어 현장 방문 자체를 증명하지는 않습니다. 서버는 유효한 본인 호출, 기기 ID, 호출 기한과 사용 기록을 검증합니다.

## 현장 확인과 이력

| 현장 상태 | 기록과 처리 |
| --- | --- |
| 작동은 끝났지만 빨래가 남음 | 미수거 확인, 호출 해제, 신고자 순번 복원, 기기 재배정 차단, 현재 이용자 재알림 |
| 아직 작동 중 | 별도 상태 오류 기록, 미수거 건수와 분리 |
| 고장 | 배정 제외, 운영자가 현장에서 확인하고 복구 |
| 수거 완료 | 현재 이용자가 자기 사용 기록을 종료 |
| 빈 기기 확인 | 같은 종류의 대기줄 참여자 또는 운영자가 QR에서 확인, 확인자에게 우선권 없음 |

미수거 확인을 위해 5분을 기다릴 필요는 없습니다. 기록은 벌점이나 고의 지연 판정이 아닙니다. 호출 만료와 알림 실패만으로 미수거 기록을 만들지 않습니다.

기기, 사용 기록, 신고자, 호출 시각, 신고 시각, 당시 예상 종료와 해결 시각을 보존합니다. 신고 저장과 호출 해제, 순번 복원, 기기 차단과 알림 예약은 같은 트랜잭션으로 반영합니다. 먼저 수거가 완료됐거나 새 사용이 시작된 뒤의 오래된 신고는 거절합니다.

본인은 관련 기록만 볼 수 있고 운영자는 신고 상세 계정 ID를 확인합니다. 공개 현황에는 계정 이름과 이메일이 없습니다. 진행 중 기록은 모두 조회하고 종료된 본인 대기, 사용, 신고 이력은 합쳐 최근 200행을 조회합니다. 이전 이력도 DB에서 삭제하지 않습니다.

## 운영 설정

| 설정 | 용도 |
| --- | --- |
| `APP_ORIGIN` | 정확한 서비스 origin. 운영에서는 HTTPS 주소 |
| `GOOGLE_CLIENT_ID` | 웹 애플리케이션 OAuth 클라이언트 ID |
| `GOOGLE_CLIENT_SECRET` | OAuth 비밀 값. Worker secret에 보관 |
| `ADMIN_GOOGLE_SUBS` | 운영자 Google sub 목록. 쉼표로 구분하며 이메일 사용 금지 |
| `VAPID_PUBLIC_KEY` | Web Push 공개 키 |
| `VAPID_PRIVATE_KEY` | Web Push 비밀 키. Worker secret에 보관 |
| `QUEUE_ENABLED` | 최초 시범 운영 활성화. 저장소 기본값 false |

Google Cloud에서 OAuth 웹 클라이언트를 만들고 승인된 리디렉션 URI를 아래 주소로 등록합니다. 요청 범위는 `openid email`만 사용합니다. Google 토큰을 지속 보관하지 않습니다.

```text
https://tmi-laundry.hanroona8844.workers.dev/api/auth/callback
```

운영자 sub는 실제 학교 로그인 후 본인 `/api/auth/me`의 ID로 확인합니다. 임의의 이메일이나 클라이언트 전달 값을 운영자 권한으로 사용하지 않습니다.

VAPID 키는 서버에서 한 번 생성하여 안전한 위치에 보관하고 비밀 값은 `wrangler secret put`에 표준 입력으로 넣습니다. 로그, Git, 채팅에 비밀 값을 붙여 넣지 않습니다. 로컬에서는 Git에서 제외된 `.dev.vars`를 사용합니다.

```sh
npx wrangler secret put GOOGLE_CLIENT_ID
npx wrangler secret put GOOGLE_CLIENT_SECRET
npx wrangler secret put ADMIN_GOOGLE_SUBS
npx wrangler secret put VAPID_PUBLIC_KEY
npx wrangler secret put VAPID_PRIVATE_KEY
npm run db:migrate:remote
npm run deploy
```

처음 활성화하면 기존 익명 기록을 사용 기록으로 가져오되 소유자는 연결하지 않습니다. 익명 기록에는 수거 알림을 보낼 수 없습니다. 기록이 없는 기기는 미확인으로 시작합니다. 현장에서 운영자 또는 같은 종류의 대기줄 참여자가 빈 기기를 확인해야 배정할 수 있습니다. 기존 기기 ID와 QR 주소는 유지합니다.

**운영 중 일시중지는 운영자 화면의 ‘새 대기와 배정 중단’을 사용합니다.** 진행 중 호출, 사용, 수거와 취소는 유지합니다. `QUEUE_ENABLED=false`는 최초 설정용이며 운영 중 중단이나 롤백 수단으로 사용하지 않습니다. 활성화된 기기의 익명 API 변경은 플래그를 꺼도 차단합니다.

## 알림 발송

브라우저의 알림 허용과 해당 계정의 Push 구독이 있어야 대기에 참여합니다. 구독은 계정별 최대 5개입니다. 현재 브라우저 구독을 별도로 확인하고, 로그아웃하면 이 브라우저의 구독만 해제합니다.

서버는 Web Push 암호문과 VAPID 서명을 만들어 브라우저 Push 서비스로 보냅니다. 상태 변경 뒤와 1분마다 outbox를 처리합니다. 서버가 접수한 발송 결과는 최대 3회 시도하며, 전송 접수를 실제 기기 도착이나 열람으로 표시하지 않습니다. 만료된 구독은 비활성화합니다. 호출 알림의 TTL은 남은 호출 기한 이내입니다.

동시 발송 결과는 lease token으로 검증하고 묶어서 저장합니다. 전송 성공 후 DB 저장 전에 서버가 중단되는 경우 재전송 가능성이 있으므로 동일 알림 tag로 중복 표시를 줄입니다. 정확히 한 번의 외부 Push 도착은 보장하지 않습니다.

아이폰과 아이패드는 홈 화면에 추가한 웹 앱에서 알림을 허용해야 합니다. 서비스 워커는 알림과 같은 origin의 링크 열기만 처리하며 API와 인증 응답을 캐시하지 않습니다.

## API와 저장 구조

| 경로 | 용도 |
| --- | --- |
| `/api/auth/login`, `callback`, `me`, `logout` | 학교 로그인과 본인 세션 |
| `GET /api/queue` | 공개 기기와 본인의 대기, 사용, 현장 확인 |
| `POST /api/queue` | join, ready, cancel, start, pickup, adjust, report, confirm_empty, recover, pause, resume |
| `GET /api/queue/admin` | 운영자용 현장 확인 상세 |
| `/api/push` | 본인 브라우저 구독 조회, 등록과 해제 |
| `POST /api/push/test` | 본인 구독으로 시험 발송. 최소 30초 간격 |

변경 API는 세션과 Origin, 입력값을 검증합니다. 요청 ID를 재사용하면 같은 변경을 중복 적용하지 않습니다. 시간 수정과 수거는 사용 기록 ID와 버전을 요구합니다.

D1의 `queue_meta` revision과 무작위 쓰기 token을 조건부 갱신합니다. 이어지는 모든 쓰기도 같은 token을 확인하는 batch 트랜잭션으로 처리합니다. 조건부 갱신이 0행인 경우도 후속 쓰기가 실행되지 않도록 막습니다. 기기, 대기표, 사용, 현장 확인, 발송 기록은 `queue_records`의 별도 행에 저장하며 완료된 이력은 보존합니다.

## 검증과 현장 시작 조건

```sh
npm run typecheck
npm test
npm run build
npm run preview
npm run test:api
```

기존 API 검증은 대기제를 끈 로컬 서버에서 실행합니다. 별도 대기 API 검증은 `.wrangler/queue-test` 전용 DB와 테스트 세션으로 실행하며 실제 학교 OAuth나 실제 Push 도착을 대신하지 않습니다. 테스트용 키는 의도적으로 유효하지 않아 외부 전송 전에 실패합니다.

자동 테스트 범위는 양쪽 알림 예약, 대기자 없는 수거 알림, 순번 보존, 반복 호출 차단, 중복 요청과 신고, 동시 수거와 신고, 오래된 요청, 이용 한도, 알림 재시도, 세션 보안과 암호화입니다.

현장 시작 전에 다음을 직접 확인합니다.

1. 실제 학교 Google 로그인, 비학교 계정 거부와 운영자 권한
2. 아이폰과 안드로이드에서 웹을 닫거나 화면을 잠근 상태의 수거 알림과 호출 알림
3. 실제 알림 수신 후 5분 안에 해당 QR 시작
4. 미수거 확인 후 신고자 순번 유지와 현재 이용자 재알림
5. 기존 익명 기록 보존과 12대의 실제 초기 상태
6. 관리자 일시중지 후 새 접수와 배정만 멈추고 수거와 취소가 계속 가능한지 확인

운영 DB에 가짜 사용이나 신고를 넣는 테스트는 하지 않습니다.
