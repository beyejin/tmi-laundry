## 실제 학교 로그인과 오류 수정

Google Cloud 프로젝트 `tmi-laundry`에 웹 클라이언트 `TMI Laundry Web`을 만들고 운영 callback URI를 등록했습니다. 범위는 `openid email`입니다. 비밀 값은 Worker secret으로 저장했고 Git이나 브라우저 빌드에는 넣지 않았습니다.

실제 학교 계정으로 Google 동의를 마친 뒤 `/api/auth/me`의 본인 계정과 세션을 확인했습니다. 준비 상태 화면에서도 계정과 알림 설정을 표시합니다. 이 확인은 대기 등록과 알림 도착 검증을 대신하지 않습니다.

초기 로그인에서는 토큰 교환은 200이지만 `iat`의 `check_failed`로 간헐적으로 실패했습니다. callback 진입 시각을 토큰 수신 이후에도 검증 기준으로 사용한 것이 원인이었습니다. 1.5초 응답 지연으로 같은 오류를 재현하고 토큰 수신 후 시각을 읽도록 수정했습니다. 시계 허용 오차는 늘리지 않았고 교환 중 만료된 토큰의 거부도 검증했습니다. 로그에는 실패 단계, 허용된 코드와 항목 이름만 남기고 토큰, 이메일, 오류 원문은 남기지 않습니다.

## 운영자 지정과 실제 비학교 계정 차단

2026년 11월 5일 사용자 승인 후 실제 학교 로그인으로 검증된 Google 식별자를 `ADMIN_GOOGLE_SUBS`에 등록했습니다. 같은 계정의 `/api/auth/me`에서 `isAdmin=true`를 확인했고, 로그아웃 후 새로 로그인한 세션에서도 같은 권한을 확인했습니다. 이메일이나 임의 클라이언트 값으로 운영자를 판정하지 않습니다.

기존 학교 세션을 로그아웃하고 승인받은 개인 Google 계정의 로그인 동의를 완료했습니다. 서비스는 `authError=school_account_required`로 복귀하고 학교 계정을 사용하라는 안내를 표시했습니다. 동일 브라우저의 `/api/auth/me`는 `user=null`이었습니다.

11월 5일 01:48 KST의 원격 D1 집계에서 학교 계정 1개, 기타 계정 0개로 시험 전과 같았고 `auth_sessions=0`, `queue_meta=0`이었습니다. 개인 계정의 사용자 행과 세션이 생성되지 않은 것을 확인했습니다. 대기제와 기존 기기 상태는 변경하지 않았습니다.
