# TMI 세탁실

2생활관과 3생활관을 남녀 구역으로 나누고, 층별 세탁실의 QR로 시작을 등록해 예상 남은 시간을 공유하는 시범 운영 웹입니다.

## 배포 주소

- [세탁실 현황](https://tmi-laundry.hanroona8844.workers.dev/)
- [기기별 QR 안내문](https://tmi-laundry.hanroona8844.workers.dev/qr)
- [GitHub 저장소](https://github.com/beyejin/tmi-laundry)

## 이용 방법

1. 현황판에서 생활관, 남녀 구역, 층을 선택합니다.
2. `QR 안내문`에서 해당 위치의 기기별 안내문을 인쇄해 기기에 붙입니다.
3. 기기를 실제로 켠 다음 QR을 스캔합니다.
4. 세탁기는 **36분 시작**, 건조기는 **45분 시작**을 누릅니다.
5. 현황판에서 기기를 선택하면 남은 시간을 확인하거나 수정할 수 있습니다.

독서실 좌석 현황판처럼 선택한 세탁실의 기기를 확인합니다. 기기가 많은 곳은 세탁기와 건조기를 나누어 볼 수 있습니다. 다른 층의 같은 번호 기기는 별도 기록을 사용합니다. 휴대폰에서도 기기 선택과 조작을 나누어 보여줍니다. 다른 화면의 변경은 최대 약 10초 뒤 반영되며, 새로고침 버튼으로 바로 확인할 수 있습니다.

**표시되는 시간은 사용자가 등록한 예상값입니다.** 미등록 기기는 `미확인`, 타이머가 끝난 기기는 `예상 종료`로 표시합니다. 빨래가 수거됐거나 기기가 비었다는 뜻은 아닙니다. 3생활관 여자 구역의 학교 로그인 대기제를 구현했으며, 기본 배포에서는 운영 설정 전까지 기존 시간 등록 방식을 유지합니다.

## 로컬 실행

Node.js 24 이상이 필요합니다.

```sh
npm ci
npm run db:migrate:local
npm run build
npm run preview
```

`http://127.0.0.1:5173`에 접속합니다. 개발 중에는 `npm run dev`를 쓸 수 있습니다. 로컬 QR은 같은 컴퓨터에서만 접근할 수 있으므로 기숙사에 붙일 QR은 배포한 웹사이트의 `/qr`에서 인쇄해 주세요.

## 검증

```sh
npm run typecheck
npm test
npm run build
# 별도 터미널에서 npm run preview를 실행한 뒤
npm run test:api
```

단위 검증은 실제 SQLite에서 종료 시각, 중복 등록, 동시 수정, 입력값 검사를 확인합니다. API 검증은 로컬 서버에서 2생활관 남녀 각각 1층 세탁기 12와 건조기 6, 3생활관 남녀 각각 2층 세탁기 2와 건조기 1, 3생활관 여자 3층 세탁기 2의 총 9대를 잠시 변경한 뒤 등록을 취소합니다. 운영 서버를 수정하지 않도록 로컬 주소로 고정했습니다.

## Cloudflare 배포

Cloudflare Workers가 웹과 API를 제공하고 D1이 공용 상태를 보관합니다. 로컬 저장소만 쓰는 데모가 아니므로 서로 다른 휴대폰에서도 같은 현황을 볼 수 있습니다.

최초 설정:

```sh
npx wrangler login
npx wrangler d1 create tmi-laundry
```

생성된 database_id를 `wrangler.jsonc`의 D1 바인딩에 넣은 다음 배포합니다.

```sh
npm run db:migrate:remote
npm run deploy
```

인증 정보는 Git에 저장하지 않습니다. 이 저장소는 유료 플랜 변경이나 도메인 구매를 포함하지 않습니다.

## 코드 구조

- `app/page.tsx`: 기기 현황판과 시작 및 수정 화면
- `hooks/use-laundry.ts`: 서버 동기화, 시간 보정, 요청 중복 및 오래된 응답 방지
- `lib/laundry.ts`: 기기 정의, 입력 검증, 동시에 등록할 때 충돌을 막는 SQL
- `lib/laundry-store.ts`: D1 접근과 API 응답
- `app/api/machines/`: 현황 조회 및 변경 API
- `app/qr/`: 기기별 QR 안내문과 인쇄
- `drizzle/`: 데이터베이스 스키마

React와 Vinext, Cloudflare Workers 및 D1을 사용합니다. UI는 Astryx 컴포넌트와 토큰을 사용합니다.

## 시범 운영 범위

로그인 없이 기기 상태를 등록하고 수정할 수 있습니다. 등록 누락과 잘못된 입력을 사람이 확인하는 소규모 시험용입니다. 확인된 시설은 아래와 같으며, 남녀 구역의 기기와 이용 기록은 따로 관리합니다.

| 생활관 | 구역 | 위치 | 구역별 세탁기 | 구역별 건조기 |
| --- | --- | --- | --- | --- |
| 2생활관 | 여자, 남자 각각 | 1층 | 12대 | 6대 |
| 3생활관 | 여자, 남자 각각 | 2층부터 5층 | 층마다 2대, 총 8대 | 층마다 1대, 총 4대 |

전체 10개 세탁실에 세탁기 40대와 건조기 20대가 등록되어 있습니다. 모든 구역의 기본 시간은 세탁 36분, 건조 45분입니다. 기기 자동 감지와 카메라는 포함하지 않습니다. 학교 로그인, 공용 대기표, 양쪽 Web Push와 미수거 확인은 3생활관 여자 구역의 대기제를 활성화했을 때 적용합니다.

위치 정보가 없던 이전 QR은 새 위치별 QR로 다시 인쇄해 주세요. 이전 시범 기록은 데이터베이스에 보존하며, 실제 위치를 알 수 없으므로 특정 층으로 자동 이전하지 않습니다.

다음 단계는 시범 세탁실에 기기별 QR을 붙여 여러 휴대폰으로 등록 누락과 시간 오차를 확인하는 것입니다. 확대 운영 전에는 시험 결과에 따라 수정 권한과 실제 수거 확인 방식을 결정합니다.

## 학교 로그인과 대기제

[대기제 구현과 운영 안내](docs/queue-operations.md)에 확정한 규칙, Google 로그인과 Push 설정, 현장 시작 조건과 API를 정리했습니다.

- Google 학교 조직 검증과 사용 기록 소유자 연결
- 종류별 공용 대기줄, 각 2대 한도와 5분 QR 시작
- 현재 이용자 수거 알림과 다음 이용자 현장 확인 알림
- 미수거, 아직 작동 중과 고장의 분리 기록
- 순번 보존, 동시 요청 방지와 완료 이력 보존

기본 설정은 `QUEUE_ENABLED=false`입니다. 실제 학교 로그인, 아이폰과 안드로이드의 잠금 상태 알림, 현장 기기 상태 확인 후 시범 운영을 켭니다. 활성화 후 중단은 관리자 일시중지를 사용하며 진행 중 이용과 수거를 유지합니다.
